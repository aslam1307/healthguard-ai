# HealthGuard AI — Intelligent Care Prototype

A Streamlit educational healthcare project with a modern interface, symptom-input organizer, optional AI health-information assistant, doctor directory template, consultation request workflow, simulated wearable vitals, demo analytics, and PDF summaries.

## Features
- **Overview dashboard** using synthetic demonstration records.
- **AI Symptom Analyzer** extracts supported symptom keywords, records optional measurements, surfaces configured warning triggers, and can request cautious health-information guidance from the optional Gemini integration.
- **Doctor Consultation** displays doctors from `data/doctors.csv` (and currently also recognizes the supplied `data/doctors.csv.csv` file) and saves demo consultation requests locally to `data/consultation_requests.csv`.
- **AI Health Assistant** for general educational health questions.
- **Fitness AI Coach** builds a starter gym or home routine from a user's goal, experience, weekly availability and food preference, with meal inspiration and a session-only daily check-in. Coaching nudges in this prototype are rule-based, not generated by a live fitness model.
- **Health Monitor** uses simulated vitals only; it is not connected to a real wearable.
- **Model Insights** and **Screening Reports**.

## Quick start
1. Use Python 3.11 if possible.
2. Create and activate a virtual environment.
3. Install dependencies: `pip install -r requirements.txt`
4. Copy `.env.example` to `.env` if you want to configure optional AI integration.
5. Run `streamlit run app.py` from the `HealthGuard_AI` folder.

## Share a hosted demo

The app currently runs only on your computer. To give a colleague a link, deploy it to [Streamlit Community Cloud](https://share.streamlit.io/) from a GitHub repository:

1. Create a GitHub repository and push this project, including `models/healthguard_model.deploy.joblib` and `requirements.txt`.
2. Keep `.env`, `.venv`, the original uncompressed model, generated reports, and local demo records out of Git. The included `.gitignore` does this.
3. In Streamlit Community Cloud, choose **Create app**, select the repository and branch, and set the app file to `app.py`. Choose Python 3.12 in **Advanced settings** if the option is shown.
4. For an invited-colleagues link, keep the GitHub repository private, deploy it as a private app, and invite your colleague by email in the app's sharing settings. For an anyone-with-the-link app, use a public repository and public app instead.

The deployed app is a demo only. Streamlit Community Cloud's local files are not durable storage, so consultation requests written to `data/consultation_requests.csv` may disappear when the app restarts. Do not use this hosted prototype to collect real patient information. Do not upload `.env` or put API keys in source code; add any needed credentials only through the hosting provider's secrets settings.

The deployment model artifact is compressed and included separately as `models/healthguard_model.deploy.joblib`. The app prefers it automatically; local development can continue using `models/healthguard_model.joblib`.

The included model and demo data are for educational use. If model files are missing, run the project's dataset generation and training scripts as appropriate.

## Add doctor details later
1. Download the doctor details CSV template from the Doctor Consultation page.
2. Fill it only with real, permissioned, verified clinician details.
3. Save a copy named `data/doctors.csv`.
4. Restart or refresh the app. The Doctor Consultation page reads the CSV automatically; `data/doctors.csv` takes precedence if both filenames exist.

`booking_url` should be a trusted HTTPS appointment page. Do not publish unverified profiles or personal phone numbers without permission.

## Consultation requests
The current demo saves form submissions to `data/consultation_requests.csv` on the machine running Streamlit. It does **not** send a message to a doctor, book an appointment, or confirm a consultation. Before real deployment, add authentication, secure storage, access controls, consent and privacy notices, encryption, audit logging, and a real appointment/contact integration.

## Important medical safety limitations
- This is an educational prototype, not a medical device or clinical decision-support product.
- It does not diagnose disease, prescribe treatment, or replace a licensed clinician.
- Symptom keyword extraction is basic and may miss or misunderstand symptoms. A lack of warning flags does not rule out an emergency.
- The vital-sign stream is synthetic, and dataset/model output must not be treated as clinical evidence.
- For severe or rapidly worsening symptoms, contact local emergency services or seek urgent medical care rather than relying on this application.
- Do not enter identifiable or highly sensitive patient information into this demo. Do not deploy with real patient data without qualified security, privacy, and clinical review.
- Fitness plans are general wellness suggestions, not medical advice, individualized nutrition prescriptions, or injury rehabilitation. Stop exercising if you feel pain or unusual symptoms and ask a qualified professional when you have a health concern.
